# ParaScale 生产工具功能与性能验收基线

基线日期：2026-11-24；模型与优化器状态显存口径于2026-11-26确认。

依据：用户提供的功能指标截图及当前工程目标。本文件定义必须交付的目标，不是已经通过的验收报告。既有小模型、CLIP 或短程测试不能替代指定模型的最终验收。

## 1. 交付目标

ParaScale 应交付统一工程中的两类可用工具：

1. 并行训练工具：支持数据并行、模型并行等多种方式，提供至少一种针对 Transformer 的训练加速方法，并支持指定 LLaMA-7B 的微调训练加速。
2. 推理优化工具：支持模型量化、知识蒸馏及模型剪枝，覆盖 Transformer 和 diffusion 至少两类生成式模型，提供可复现的实际推理加速。

两类工具共享配置、模型与数据身份、设备能力、产物契约、诊断和报告，不要求拆成两个独立代码仓库。保持成熟后端与算子的复用，不把自行实现底层内核作为未经确认的额外要求。

## 2. 需求与验收

| 编号 | 必须具备的能力 | 最低验收内容 | 当前证据边界 |
| --- | --- | --- | --- |
| PAR-01 | 可复用并行算子/执行组件 | 明确支持的形状、dtype、布局和设备；验证前向、梯度、通信组与数值容差；独立测量算子及整体收益 | 已有张量并行、流水线和通信组件，不等于通用算子库全部完成验收 |
| PAR-02 | 数据并行 | 同数据、全局 batch、精度、优化器和目标函数的单卡/多卡对照；有效样本吞吐、扩展效率、显存、质量和恢复 | 部分 CLIP/语言模型场景已有证据；不能外推所有模型 |
| PAR-03 | 模型并行 | 张量并行 TP、流水线并行 PP 分别测试；验证正确性、参数/优化器状态、容量和吞吐 | 部分场景通过；TP 存在负扩展，不预设一定更快 |
| PAR-04 | 多维组合并行 | 对 DP×TP、DP×PP、TP×PP 的支持组合逐项验收，明确不支持的组合 | 四卡可测二维组合；非平凡 DP2×TP2×PP2 需八个 rank，当前每 GPU 单 rank 的验收需八卡；四卡二维结果不等于三维实测 |
| TRN-01 | 至少一种 Transformer 训练加速方法 | 公开算法与执行机制，和合理原生基线同口径比较；证明不是更换数据预算或降低质量取得的数字 | 既有预取、精度和执行优化是候选证据，不自动满足指定 7B 微调指标 |
| TRN-02 | LLaMA-7B 微调 | 采用meta-llama/Llama-2-7b-hf基座版；冻结合法权重revision、数据和微调方式；实际CLI执行、检查点恢复、独立质量验证、速度和显存记录 | 已核验仓库revision元数据，但合法权重访问尚未完成，TinyLlama不能替代 |
| TRN-03 | 优化器状态显存相比AdamW降低至少40% | 同模型、可训练参数、布局和计算精度；实际更新后统计全部优化器状态的CUDA存储，包括量化尺度与误差补偿；同时验证质量、恢复和训练开销 | 完整状态统计及补偿恢复精度问题已修复；无补偿四位优化器尚未通过小模型质量筛查，不能推荐为生产方案，尚无7B达标证据 |
| INF-01 | LLaMA-7B FP16 推理 | 模型完整重载，实际生成，吞吐、prefill、decode、端到端延迟、显存和质量 | 已增加 CUDA 浮点 FP16 动态缓存入口及小型 Llama 功能对照；指定 7B 仍待验收。FP16 不称为 INT8 量化能力 |
| INF-02 | LLaMA-7B INT8 量化推理 | PTQ 校准与独立评估；验证实际 INT8 内核执行、完整产物重载；对比同设置 FP16 基线 | 小模型 INT8 同产物 BF16 对照不能替代此项 |
| INF-03 | 量化感知训练 QAT | 真实参数更新、量化导出、新进程重载和实际量化推理；记录质量与训练成本 | 已有小模型限定场景；QAT 不自动优于浮点微调或 PTQ |
| INF-04 | 知识蒸馏 | 冻结教师；同初始化同预算的学生 CE 基线；独立质量对照；不依赖教师的学生导出和推理；实际速度/显存收益 | 随机模型功能测试不构成知识迁移质量证据 |
| INF-05 | 模型剪枝 | 明确结构化或非结构化方案；实际压缩/稀疏执行、导出和重载；报告质量与端到端收益 | 已增加Llama MLP结构化通道删除，CPU/A6000小模型验证结构、导出重载和继续训练；预训练质量与端到端加速尚未验收，不把幅值排序基线称为质量保证 |
| INF-06 | Transformer 生成推理加速 | 至少一个实际 Transformer 生成模型，记录输入输出长度、batch、精度、缓存与编译策略；分离冷启动和稳态 | 有限形状的小模型结果已有证据，不等于通用生成服务 SLA |
| INF-07 | diffusion 生成推理加速 | 至少一个实际扩散模型，固定权重、提示词、种子、分辨率、调度器、精度与采样预算；质量与速度联合验收 | 已完成 SD 1.5 eager 批量推理与同 batch 原生对照；批量配置有吞吐收益。编译候选未通过像素保真门禁，独立生成质量及完整生产验收仍未完成 |
| OPS-01 | 生产工具可用性 | 安装、能力检查、配置校验、错误说明、产物完整性、恢复、资源释放、文档和可运行 examples | 单个 CLIP 长跑通过，不等于所有上述路径通过 |

本表要求系统同时具备多种方法，不要求把量化、蒸馏、剪枝和所有并行方式任意叠加。组合功能须单独声明、单独验证；未验证组合应明确拒绝。

## 3. 40% 指标定义

用户于2026-11-26明确选择“仅优化器状态显存”，验收公式固定为：

`(B_AdamW_state_cuda - B_candidate_state_cuda) / B_AdamW_state_cuda >= 0.40`

其中B为实际初始化并执行更新后的优化器持久状态CUDA存储字节；包括一阶/二阶矩、量化数据、尺度/偏移、误差补偿及其他CUDA状态张量，按底层存储去重，不重复计算别名。CPU/offload状态单独报告，不将状态转移包装成压缩。分布式逐rank及全局合计均报告，基线与候选使用相同布局，不能靠增加分片数取得这项算法收益。

不包含模型权重、梯度、激活或临时反量化张量；这些开销另以峰值显存和完整训练时间披露。40%不代表整体显存节省或训练提速。配置相同的实际AdamW状态才是正式基线，按参数量估算的FP32矩状态只能用于预检，不能代替7B实测。

已有FourBitAdamW/FourBitSGD及配置工厂接入，当前支持native/native_ddp，不支持DTensor或native_parallel。优先核验已有实现：FP32参数、group128条件下，两份FP32补偿使持久张量状态理论上超过FP32矩参考约14.06%；FP16补偿理论节省35.94%；关闭补偿约85.94%，但需独立质量和恢复验证。不得沿用只统计量化载荷而漏算补偿张量的旧节省比例。

小幅值量化的固定绝对epsilon导致状态失真，已改为仅保护零范围分组的除法。该数值修复不等于完成四位优化器质量验收：现有无补偿方案在真实小模型独立验证中仍未通过预设质量门槛，也未取得同预算吞吐优势。不得自动启用无补偿模式或将其显存节省单独包装为生产达标。

基线必须是合理优化的 AdamW 实现，并记录 foreach/fused、状态 dtype、梯度 dtype、offload、分片和累积配置。不能故意采用低效基线；LoRA 与全参数微调的可训练参数量不同，未经确认不能用其对比冒充优化器本身收益。候选算法的来源、是否原创与性能结论分别说明。

## 4. 模型与资源约束

- 用户授权由工程方选定常用版本，采用 `meta-llama/Llama-2-7b-hf` 基座模型。获取须遵守[官方模型卡及许可](https://huggingface.co/meta-llama/Llama-2-7b-hf)，核验访问授权并冻结具体revision。不能把TinyLlama、SmolLM或其他7B模型改名替代；它们仅为开发验证资产。
- 指定版本确定后冻结模型 revision、配置、tokenizer 和权重哈希；不得在实验中静默切换基础模型。
- 主要开发资源为 156 节点 A6000，训练对照默认最多四卡；第五卡仅用于隔离任务，不与计时任务争抢资源。训练和推理计时分开执行。
- 模型并行解决容量问题不等于吞吐一定提高；每个布局必须给出真实结果，保留失败和负扩展数据。
- diffusion 模型和数据先做选型；不将未指定的某种 Stable Diffusion/DiT 架构自行视为用户硬性指定，也不把图像分类或 CLIP embedding 当作 diffusion 推理。

## 5. 共同性能与质量口径

1. 数据分为训练/校准、开发验证和最终测试；明确来源、去重范围和预训练污染未知项。不得把训练集结果作为独立质量验收。
2. 同硬件、软件版本、模型、精度、输入数据和有效计算预算；异构条件只能作为另一个实验，不直接合并加速比。
3. 报告 steady throughput、端到端时间、冷启动/编译成本、allocated/reserved/NVML 显存边界；不混用不同计时范围。
4. 生成模型报告实际输出 token 数；不同长度和 EOS 策略不得伪装成等预算对照。生成质量与教师强制困惑度是不同证据。
5. diffusion 若减少采样步数或更换 scheduler，必须单独作为算法变化并重新验证质量；不同分辨率/步数的速度差异不是纯执行优化。
6. 剪枝必须区分置零、真实结构缩小与硬件支持的稀疏内核。稀疏率、文件尺寸变小和运行更快分别计量。
7. 蒸馏学生变小带来的速度收益归因于学生执行结构；KD 本身对质量的贡献必须与同结构、同预算的非蒸馏学生比较。
8. 正式性能结果采用预热、独立配对重复、固定停止条件；profile 不混入计时。试验不达标时先做机制分析并检索原始论文/官方实现，再允许一次有证据的修正。

## 6. 实施顺序

1. TRN-03已确认为优化器状态显存，模型选定Llama2-7B；完成权重授权/revision核验与完整状态统计修正，冻结数据及质量门槛。已有小模型作为开发资产保留，不用小模型性能实验替代7B验收。
2. 在指定 7B 模型上建立原生 AdamW、FP16 推理和 ParaScale 的公平基线；复核内存容量及可用并行布局。
3. 完成 7B INT8 PTQ 的质量、导出与实际内核加速闭环，再按需求补 QAT。
4. 针对已确认的 40% 指标，选择有研究与硬件依据的训练优化方法，完成小规模正确性验证后进行 7B 实测。
5. 完成蒸馏、剪枝的真实产物与质量/速度验收，不用单项 API 存在代替产品路径。
6. 引入独立 diffusion workload，复用推理执行与报告边界，完成第二类生成模型的加速验收。
7. 汇总要求到 examples、软需、软设、用户手册和统一的外部性能报告；通过 PR 交付，不能直接推送 main。

后续步骤可以根据共享依赖调整，但不得删除本表要求以便提前宣布完成。HTTP/gRPC 服务、通用强化学习或重新实现 Megatron 不是这张截图额外要求的交付；若新增，应另立验收条目。
