# ParaScale 试用版 README 设计

## 目标

README 面向首次接触 ParaScale 的外部试用用户，以当前 Refactor 分支的真实能力为准，完整回答“是什么、为什么使用、如何安装、如何首次运行、如何进一步验证、能力边界在哪里”。

## 信息结构

README 依次提供以下一级入口：

1. 特性
2. 安装
3. 快速开始
4. 文档
5. 示例
6. API 参考
7. 架构设计
8. 测试
9. 版本历史
10. 许可证

开头设置与上述章节对应的目录导航。快速开始采用 `doctor -> plan -> train/infer -> benchmark -> checkpoint` 用户旅程，形成从环境诊断到训练结果验证的闭环。

## 内容原则

- 参考 master 分支的分区和阅读节奏，不继承已经失效的脚本、路径和能力描述。
- 所有命令必须能由当前统一 CLI 或 `examples/` 中的运行脚本执行。
- 区分已验证能力、可选依赖、实验能力和后续路线，不将 dry-run、synthetic 或 smoke 描述为生产性能证据。
- 简要说明 native-DDP、FSDP 和 DeepSpeed 的适用边界，不宣称无同口径证据的性能优势。
- GPU 与 Ascend 共用一套框架说明，硬件差异通过 extras、运行环境和示例目录体现。
- README 保持用户导向；详细设计、需求、远程测试说明和历史测试记录通过链接下沉到 `docs/` 与 `tests/`。

## 验收标准

- 所有目录锚点与用户指定顺序一致。
- README 中不存在 `doc/`、已删除模块或失效脚本引用。
- 示例配置、脚本和文档链接均存在。
- 快速开始命令通过 CLI dry-run 或对应轻量验证。
- Markdown 保持 UTF-8，代码块和相对链接可在 GitHub 正常阅读。
